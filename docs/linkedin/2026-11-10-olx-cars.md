The whole tool, free: github.com/aswathas/olx-car-search

OLX India has no public API, so I read the one its own frontend calls. Here is the whole ledger, nothing rounded:

- API key: ₹0
- Proxy: ₹0
- Account: ₹0
- Dependencies: 1 (curl_cffi, impersonate="chrome")
- HTTP clients that got through: 1 of 4
- OLX requests per search: 1
- Cars per response: 20
- Python: 592 lines, plus 152 of tests
- Tests: 8 (5 offline, 3 live, one full MCP round-trip)

The obvious path was a scraping proxy. I never bought one, so I never found out what it costs. A proxy would have hidden the problem instead of solving it.

curl, Python requests and headless Chrome all got a connection reset from OLX — before a byte of HTML arrived. I watched Chrome print ERR_HTTP2_PROTOCOL_ERROR instead of a page, and that is a TLS-layer problem wearing an HTTP costume. Chrome itself was blocked, which is the part that took me the longest to believe. curl_cffi sends a real Chrome handshake, so it got 200 OK and clean JSON.

The surprise came later. OLX ignores unknown query parameters silently, so a filter that does not exist looks exactly like a filter that worked. Nothing errors. The filter just returns everything. The only honest check was OLX's own applied_filters echo in the response, so the tool prints it on every run.

136 used cars in Chennai between ₹3,00,000 and ₹6,00,000, 2018 onwards, in one request. Each car carries price, year, km, fuel, transmission, owner count, city, seller type and the live listing URL, so an agent can rank them without opening a browser.

One handshake beat four clients.
